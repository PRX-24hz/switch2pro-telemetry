# `tools/write/` — 会向设备写入的脚本（默认不要运行）

> [English](README.en.md) · **中文**

---

## 这个目录为什么存在

本仓库的主线是**只读采集**：`tools/` 下的所有脚本、以及**全部结论**，都不依赖向设备写入任何字节。

但这个目录里的三个脚本**会写设备**。它们存在的唯一原因，是为了回答一个具体问题：

> 关闭 Steam 之后，手柄为什么一帧 `0x05` 都不发？

答案是「设备需要一次激活」（见 [`docs/discovery-imu.md` §8.1](../../docs/discovery-imu.md)）。
为了确认这一点、并尝试自己复现激活，我们向设备发过报文。**发出去的东西来自 USBPcap 抓包的原样回放，
没有构造任何新命令**，但仍然属于写入。

按本仓库的规矩，这类代码不能和只读工具混在一起——**混在一起，「只读」就变成了一句无法验证的口号**。
所以它们被隔离到这里，并且 `tools/audit_readonly.py` 会单独列出它们。

## 清单

| 脚本 | 做什么 | 结果 |
|---|---|---|
| `send_ctrl.py` | 用控制传输 `HidD_SetOutputReport` 发送单条输出报告 | 全部被系统层拒绝（`err=87` / `err=31`） |
| `send_activation.py` | 用 `hid.write()` 发单条报告 | 返回 `-1`（中断 OUT 要求 64 字节整包） |
| `replay_activation.py` | 按顺序回放完整的 19 条激活序列，逐个试 report ID | 16 个候选 ID 全部失败 |

**三个脚本都没能激活设备。** 最终结论是：命令走的是 `MI_01` vendor 接口，而 HID 层写入走不通，
需要 WinUSB 绑定（Zadig）才能自己实现激活。本仓库**不提供**那条路径——成本高于收益，
用现成软件激活一次即可（激活后关闭软件，数据照常输出）。

## 如果你确实要跑

```bash
cd tools/write
python replay_activation.py            # 逐个 report ID 试激活
```

跑之前请读一遍脚本顶部的注释。已知风险：发错报文可能让手柄短暂无响应，
**拔掉 USB 重插即可恢复**（这是实测过的）。不会变砖、不会改固件、不会持久化任何配置——
但也**不要**在没有备份理解的情况下修改报文内容。

## 为什么不用更彻底的做法：删掉它们

因为这些失败本身是结论的一部分。「HID 层发不进去」和「必须走 vendor 接口」是我们花了几个小时
试出来的，删掉脚本就等于删掉证据。留在这里、标注清楚、独立审计，比假装没试过诚实。
