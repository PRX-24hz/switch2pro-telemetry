## 3. 接入拓扑（实测组合）

| 项 | 值 |
|---|---|
| 线材 | 原装 USB-C 数据线 |
| 中转 | **两层 Genesys Logic 外置 hub 串联**（`VID_05E3 PID_0608` ×2） |
| 主机 | Windows 11 PC，USB HID 直连（非独占共享句柄） |
| 同时运行的软件 | 见 §6「激活」——数据采集与软件是否运行**无关**，但**激活那一步**由 **Steam 客户端**完成（停在登录界面即可，不需登录） |

**完整设备树**（`Get-PnpDevice` 逐级上溯）：

```
Intel USB 3.20 控制器 (PCI\VEN_8086&DEV_7A60)
└─ USB 根集线器  (4&2f9de05b&0&0)
   └─ 通用 USB 集线器  VID_05E3 PID_0608 (Genesys Logic)
      └─ 通用 USB 集线器  VID_05E3 PID_0608 (又是同一型号)
         └─ Switch 2 Pro Controller
```

LocationInfo = `0000.0014.0000.003.002.003.000.000.000`（端口链 3.2.3）。

> **为什么必须写明这一条**：所有数据都采自「经两层外置 hub」这条链路。
> 对 250 Hz 本身没有影响（USB 帧是 1 ms，250 Hz 是它的 4 倍），但 hub 转发会引入缓冲，
> **涉及微秒级抖动的判断会受影响**；红灯常亮也可能只是 hub 的供电水平，不代表直连供电。
> 尚未做「直插主板 vs 经 hub」的对照，这是本仓库一个未声明的时序前提。

**实测链路质量**：250 Hz、连续 200+ 秒 0 掉帧；长时间监测累计掉帧 ≈ 0.0006%。

## 4. 如何读手柄固件版本（只读通道读不到）

在 Switch 2 主机上：

```
设置 → 控制器与传感器 → 更新控制器
```

页面会显示当前手柄固件版本。抄下来填进上表即可。

（读版本本身需要向设备发命令，违反本仓库的只读原则，所以只能人工抄。）

**但有一个只读的替代品：`bcdDevice = 0x0201`。** 它来自 USB 设备描述符，`hid.enumerate()` 的
`release_number` 字段直接给出，**不需要发任何命令**：

```python
import hid
for d in hid.enumerate(0x057E, 0x2069):
    print(hex(d["release_number"]))      # 0x201
```

它**不等于** Switch 界面上那个固件版本字符串，但足以判断"两台设备是不是同一版"。
旁证：SDL 给这台设备生成的 GUID 里 `[12:14]` 就是 `01 02`（见
[`docs/protocol.md`](../docs/protocol.md) §3.1）。据公开记录，HIDMaestro 标注的固件是 `1.1.5`，
与本机的 `0x0201` **不同**，说明 bcdDevice 与那个版本号确实不是一回事——这正是需要写明区别的原因。

## 6. 激活前提（最容易被误判的一条）

设备**不是插上就发数据**。未激活时：枚举正常、PnP 全绿、读到的帧数为 **0**。

| 状态 | 表现 |
|---|---|
| 未激活（刚插上 / 刚拔插过） | 0 帧；按键也不唤醒 |
| 被主机命令激活后 | **直接 250 Hz**，无爬坡 |
| 激活后关掉发起软件 | **流不中断**（Steam 全退出后仍 250.2 Hz） |
| 拔线重插 | 退回未激活 |

激活命令走 **`MI_01` vendor 接口**，不走 HID 接口 `MI_00`——所以任何 HID 层写入都进不去。
命令序列与语义见 [`docs/discovery-imu.md`](../docs/discovery-imu.md) §8.1。

> 本仓库**没有实现激活**。所有数据都采自「已被 Steam 激活」的设备。
> 这一点必须写进方法，否则别人照着重跑只会得到 0 帧。

**激活手段（实测）**：启动 Steam 即可接管，**停在登录界面、不登录也行**；关掉 Steam 后流不中断。
「登录前就能接管」说明起作用的是 Steam 客户端的本地控制器服务，与账号配置无关。

**未测**：其他软件（SDL 游戏、HIDMaestro、Linux `hid-nintendo`）是否也能激活；
Steam 里关闭「控制器支持」后是否仍接管（**当前 Steam 版本里没找到这个开关**，可能已移除或按设备隐藏）；
不同 Steam 版本是否一致。
**激活这一步挂在会自更新的第三方客户端上，这是本仓库可复现性的天花板。**

> **一个可观察的旁证**：Steam 的「控制器 → 控制器布局 → 检测输入」页面会实时响应按键，
> 说明 Steam 确实已经打开并读取了这台设备。该页面同时显示**序列号**，
> **不要截图公开**——这与 pcap 里设备描述符带序列号是同一类风险。
