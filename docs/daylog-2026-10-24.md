## 2. 今日确立的（按证据强度排）

### 2.1 最硬：时钟回绕 = 2³² ticks @ 3 MHz

```
预测点      1,431,655.765 ms
历次实测    1,431,650 / 1,431,652 / 1,431,651 …（偏差 −5.8 / −3.8 / −4.8 ms）
时基回归    658 s / 330 点 → +10 ppm（3.00003 MHz），物理周期 1,431.641 s
```

这是全天唯一"**先预测、后验证、且多次重复**"的结论。它同时给出一个可用判别器：

> 归零点偏离 `1,431,65x` 超过约 1 s → 是**重置**；落在该区间 → 是**回绕**。

**关于 12:44 那次 +1.2 s 异常归零**（时间线里提到的"逐一排除 3 个假设"）——三个被排除的假设是：

1. **时基频率漂移**：若周期慢了 1.2 s，需 ~838 ppm 的漂移；但同期 `measure_tick.py` 实测 +10 ppm，
   差 80 倍，排除。
2. **无读者导致固件重起定时器**：关闭句柄 300 秒完全不读，计数器仍精确走 1:1（差 +3.2 ms），
   且期间正常回绕一次——排除"没人读就重置"。
3. **读到陈旧缓冲帧**：空闲 300 s 后的首帧比主机时刻新 3 ms 以内，Windows 不返回过期报告，排除。

结论：12:44:09.4 的回绕**按时发生了**（只是断档没采到），1.2 s 后又发生一次**独立的软重置**。
三个假设全排除后，这是唯一自洽的解释；至于软重置的触发原因，仍未知，留作开放项。

### 2.2 状态字节是位域，但"阶段索引"不成立

| 位 | 含义 | 证据 |
|---|---|---|
| b5 `0x20` | 电源在位 | 所有非零值均置位，`0x00` 清零 |
| b2 `0x04` | 有充电电流 | `0x2C/0x24/0x34/0x3C` 置位，`0x20` 清零 |
| b4:b3 | **不是**单调阶段 | 插入序列 `0→2→1→2`，反例明确 |

### 2.3 `0x20` = 充电完成，且**不是**吸收态

- 红灯同刻熄灭；
- 可维持 5h39m；
- **拔插即可退出**，不需要放电到阈值。

| B | `0x00`/`0x24` 以 **2.9 Hz** 斩波 | 15:23–21:45，6h+ |

**触发条件未知**，且"B → A"的转移**从未观测到**。
（注：这句写于日间。次日凌晨的[附录 A](#附录-a--夜间续记10-24-2136--10-25-0641) 已经观测到"斩波 → 0x20"的自行收尾，本条作废。）

### 2.5 斩波参数

```
OFF 段（0x00，断开/不充电）  284 ms（6 小时一个毫秒都没变）
ON 段（0x24，导通）           52 → 40 → 32 ms（缓慢收窄）
`0x00` 断开占比（OFF-duty）  82% → 90%（极慢上升后稳定）
ON 导通占空比               18% → 10%
频率                         2.9 Hz
```

> **术语说明**：本文的「`0x00` 断开占比」（代码里叫 `duty00`）指 **`0x00` 不充电的时间占比**，
> 与电子工程惯例（duty cycle = ON 导通占比）**相反**。读"ON 脉宽越缩、断开占比反而越高"时别懵：
> OFF 恒 284 ms，ON 从 52 缩到 32 ms，所以 OFF 占比 = 284/(284+ON) 从 84% 升到 90%，
> 而 ON 导通占空比从 16% 降到 10%。

### 2.6 读数跟着斩波摆，滞后 40~60 ms

60 秒 / 15,001 帧，按"跳变后第 k 帧"统计：

| k | → `0x24` | → `0x00` |
|---|---|---|
| 0 | 3,673 | **3,693** |
| 8 | 3,689 | 3,687 |
| 15 | **3,692** | 3,674 |

→ 单帧读数有 **±10 斩波噪声**，必须跨 ≥1 个周期（350 ms）平均。

### 2.7 插线是否真充，取决于**亏电多少**

| 拔插 | 拔前读数 | 首帧 | 有无真充 |
|---|---|---|---|
| 15:21 | 3,616（已放电） | `0x24` | 有（约 1 分钟 `0x34`） |
| 18:00 | 3,676（已顶满） | `0x00` | **无** |

### 2.8 负载不影响充电决策，且维持期不掉电

39 分钟真实游玩（按键活动峰值 51%）：状态零变化、读数极差仅 4。

## 4. 今天修掉的工具 bug（每个都有教育意义）

| bug | 现象 | 根因 |
|---|---|---|
| `dclk < dwall * 0.5` 判重置 | 把一次正常回绕误判成"重置成立" | **无符号回绕当负数**——正是本项目一直在警告的错 |
| `if not wait_for(...)` | 设备明明已拔，脚本报"等不到拔出" | 成功值就是 `None`，"没找到"与"出错"同形 |
| `_pylibs` 路径多退一级 | `ModuleNotFoundError: hid` | 文件在 `tools/` 下时根目录算错；只读跑一次才暴露 |
| `play_monitor` 未捕获 OSError | 拔线瞬间进程崩，无 `[Offline]` | 只 catch 了 `KeyboardInterrupt` |
| shell 里写正则 | `\d` 变成 `/d`，解析 0 行 | 双引号转义；规则改为**正则一律写进 .py 文件** |

> **关于 §1 里 `偏=-73 ms` 与 §2.1 的 +10 ppm 符号相反**：两者不是同一个量。
> `+10 ppm` 是 `measure_tick.py` 用**单调时钟**（`perf_counter`）测的，是设备晶振相对主机单调时钟的频率差；
> `偏` 是 `log_status_transitions.py` 用**壁钟**（`time.time()`，会被 NTP 缓调）累计「Δ壁钟 − Δ设备」，
> 反映的是壁钟漂移，不是设备晶振误差。符号相反是正常的，别混为一谈。

## 附录 A · 夜间续记（10-24 21:36 → 10-25 06:41）

同一台设备、同一条链路，连续挂机 9 小时 05 分。这段数据解决了两条开放问题（#8 #9），
又冒出一个**从未见过的收尾形态**。

### A.1 收尾不是"渐消"，而是一次反转

昨天 19:59 我根据"ON 脉宽 52→40→32 ms"外推"脉宽趋零 → 切 `0x20`"。**方向完全错了。**

| 时刻 | 状态构成 | 读数 |
|---|---|---|
| 22:30–23:45 | `0x00` 89~91%（稳态，已维持 7.5 h） | 3,677 |
| 23:48–23:55 | **翻腾期**：`0x24 → 0x34(4 ms) → 0x2C(440 ms)` 循环 **38 次** | 3,72x |
| 23:59–00:09 | **`0x34` 满功率充电，约 10.5 分钟** | 3,728 |
| 00:09:35 | `0x34 → 0x3C` | 3,727 |
| 00:09:45 | `0x3C → 0x20`（转入模式 A） | 3,715 |
| 00:10–06:34 | `0x20` 100%，单调下降 | 3,708 → 3,603 |

三条硬结论：

1. **斩波维持态会自行收尾**，不必拔插；从进入维持到完成约 **8 小时 46 分**。
2. **收尾路径是 `0x2C` → `0x34`(满功率) → `0x3C` → `0x20`**，不是脉冲衰减。
3. **`0x3C` 时长 = 10,004 ms**（n=2，两次均为 10 秒整）→ 解析器必须容忍这个约 10 秒的窗口。

### A.2 一个新形态：翻腾期（churn）

23:48–23:55 共 38 次循环，每轮：

```
0x24（约 28 ms，有电流）
  → 0x34（典型 4 ms，恰好一帧）
  → 0x2C（中位 440 ms）
  → 回到 0x24
```

`0x34` 只存在 **4 ms = 一个帧间隔**，只有 250 Hz 采样才看得见。
**1 Hz 轮询的软件永远看不到这一段**——它只会看到 `0x00`/`0x24`，然后突然变成 `0x20`。

### A.4 又修掉一个自己的缺陷

审计脚本最初把 23:58 判成"重置"，因为判据是"归零点离 1,431,65x 超过 1 s 即重置"——
**而心跳间隔是 30 秒，最后一帧本来就可能早 30 秒**。

改成间隙感知判据后：`prev + 间隔 ≥ 1,431,655.765` → 回绕落在间隙内（正常）。
复核结果 **22/22 全部为回绕**，预测与实测差 −294 ~ +710 ms（整秒时间戳 + 4 ms 帧步进）。

> 这条已写进 [`protocol.md` §1.2](protocol.md)：**判别器有采样密度前提**，稀疏采样必须用间隙感知版本。
> 这是今天的**第 6 个工具/脚本 bug**（§4 那 5 个 + 这个）。
> 注意它和 §4 第 1 个 bug（`dclk < dwall*0.5` 误判重置）不是一回事：那个是**无符号减法溢出**；
> 这个是**稀疏采样下的时间戳对齐滞后**——两个独立的缺陷，恰好都表现为"把正常回绕误判成重置"。
